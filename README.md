在浏览器中运行《STEINS;GATE》角色的 E-mote 动态立绘：手臂姿势切换、触摸反应、语音与口型同步，外加一个可视化剧本编辑器。

> **本项目为非官方、非商业的二次创作，与 MAGES. / Nitroplus / M2 Co., Ltd. 均无关联。**
> 仓库**不包含**任何游戏原始素材（模型、立绘、背景、语音），也**不包含** E-mote 运行时（专有 SDK）。

## 概览

首页 `index.html` 顶部有三个页内锚点——**作品 / 角色 / 技术**，以及两个独立页面的入口：

| 入口 | 说明 |
|---|---|
| `index.html` | 角色档案页（世界观介绍 + Labmem 名鉴），纯静态 |
| `steins_gate/story/index.html` | **故事模式**：可视化编辑台词并播放，打字机 + 点击/自动推进 |
| `steins_gate/stage/index.html` | **LAB 播放页**：互动立绘（触摸反应、手臂姿势、口型同步） |

两个模式都需要[快速开始](#快速开始)中准备的运行时与素材。

## 快速开始

**三步跑起来**：

1. 安装 **Node.js 18+**；
2. 按下面的清单备好运行时与素材；
3. 双击 `run.bat`（Windows）或执行 `./run.sh`（macOS / Linux / Git Bash），浏览器打开 `http://127.0.0.1:8000/`。

克隆本仓库后**无法直接运行**——以下两类文件均被 `.gitignore` 排除，需自行准备：

**① E-mote 运行时 → `driver/`**

- 必需：`emotedriver.js`、`emotedriver.wasm`（本项目验证于 `driver_wasm_modularize` 构建）、`emoteplayer.js`
- 获取方式：向 [M2 Co., Ltd.](https://emote.mtwo.co.jp/) 申请 E-mote SDK
- ⚠️ 该 SDK 为专有软件，条款禁止再分发。**请勿将 `driver/` 提交到任何公开仓库**，本项目亦不会提供。

**② 模型与素材**

| 目录 | 内容 |
|---|---|
| `character/data/<角色>/<名称>.pure.psb.zip` | 角色模型，每个 zip 内含一个 `pure.psb` |
| `character/sounds/` | 剧情语音（可选，缺文件会静默跳过） |
| `static/background/` | 背景图，直接丢图片即可；`.thumbs/` 由页面自动生成 |
| `static/bgm/` | 背景音乐音频，直接丢文件即可；用法见[背景音乐 bgm](#背景音乐-bgm) |

素材需从你合法持有的游戏副本中提取，本项目不提供任何素材。

准备好后用 HTTP 打开（`fetch` 加载要求 HTTP，不能直接开 `file://`）：

```bash
node main.mjs --port 8000     # 或 ./run.sh 8000（macOS / Linux / Git Bash）
                              # Windows 也可直接双击 run.bat
# 访问 http://127.0.0.1:8000/
```

## 本地服务与语音

`main.mjs` 是零依赖静态服务（Node 18+，默认端口 8899；`run.bat` / `run.sh` 默认 8000，只监听 127.0.0.1）。相比 `python -m http.server`，它多了这些写盘接口：

| 接口 | 作用 |
|---|---|
| `GET/PUT /api/order` | 读写角色顺序 `character/actions_config/order.json` |
| `GET /api/thumbs`、`PUT /api/thumb` | 背景缩略图落到 `static/background/.thumbs/` |
| `GET/PUT /api/story` | 读写 `steins_gate/story/cast.json` 与 `steins_gate/story/scenes/*.json` |
| `GET /api/voice` | 列出即时台词音频（`steins_gate/story/voices/`） |
| `GET /api/voice?name=…` | 流式播放音频，支持 Range（可拖动进度） |
| `POST /api/voice`（octet-stream） | 外部导入音频落盘，上限 12MB（页面「选择音频」「音频列表」都不走这里，不写盘） |
| `POST /api/voice`（json） | 文字 → 语音合成（TTS 预留，`{"text":"…"}`） |

**即时台词的语音有三个来源**：

- **选择音频**——在面板里选本地音频，浏览器内用临时 blob URL 直接播放，不上传、不写盘。
- **音频列表**——列出 `character/sounds/` 下的文件夹与音频文件，选一个走静态路径直接播放，同样不写盘。
- **文字合成**——TTS 预留接口。设置环境变量 `EMOTE_TTS_BIN`（如 `edge-tts`）及可选的 `EMOTE_TTS_VOICE`（默认 `zh-CN-XiaoxiaoNeural`）后启用；未配置时接口返回 501、前端提示改用「选择音频」。外部命令需支持 `--voice <名> --text <文字> --write-media <文件>` 参数。**只有合成的音频会落盘**到 `steins_gate/story/voices/`。

换成其他静态服务器也能跑，只是写盘能力退化为只读——排序只在本次会话有效，缩略图只用已有文件，剧本无法保存，文字合成不可用；「选择音频」「音频列表」不依赖服务端写盘，照常可用。

## 功能概览

| 功能 | 说明 |
|---|---|
| **模型直读** | 直接解析 `.pure.psb`（PSB v4）二进制，无需反编译、预生成配置或构建步骤。模型放入 `character/data/<角色>/` 后自动出现在角色 tab；触摸反应按[动作配置指南](docs/动作配置指南.md)逐模型配置。 |
| **手臂姿势切换** | 针对 PSB 4.0 的互斥追加部件（`insert` / `delete`），在 GPU 纹理上传阶段打补丁，擦除未选中的那套手臂。适用于只支持到 3.9.8 的 SDK 运行时。 |
| **触摸反应** | 按 `charaProfile` 部位（eye / mouth / bust / top …）划分命中区，命中后从动作池随机抽一条执行，可携带语音与变量插值。 |
| **口型同步** | WebAudio 离线分析音频包络后按 rAF 查表驱动 `face_talk`；音频不可用时明确告警并跳过语音与口型，不提供第二条播放路径。 |
| **场景 UI** | 角色 tab 与造型面板、背景预览、tab 顺序调整；顺序写回 `order.json`，背景与卡片统一读 `.thumbs/` 的 720p 缩略图。 |
| **故事模式** | `/steins_gate/story/` 单页双模式：可视化编辑场景（行拖拽 / ▲▼ / 增删）+ 打字机播放器（点击 / 自动推进 / 语音 / 动作宏）。支持多角色同台、行内上下场与走位，详见[场景数据格式](#场景数据格式)。台词打完后，句末会出现一枚持续旋转的等待齿轮（从 `main.psb.m` 的 37 帧「キー待ちアイコンアニメ」烘焙成雪碧图）：前 17 帧是齿轮由一条线张开的变形进入动画（只播一次），之后 20 帧完整旋转循环，一直转到翻页；AUTO 打开时隐藏。对话框开场照 `MSGWIN.show` 复现：只用 `main/white` + `main/ウィンドウ` 两张可见贴图，白线 0–29 帧两侧擦入、30–59 帧擦出，窗底 0–59 帧擦入，末态回到 `MSGWIN.normal` 的干净常态（e-mote 内置遮罩图案 `#mask/*` 不是可见层，不叠放）。名牌底板 s/m/l/ll 四档合并成一张雪碧图 `ui/nameplate_sheet.webp`，按名字长度平移取片；名牌出场还原原作的 mesh 形变：纯白几何从正菱形横向拉成纺锤（短暂停留）再压平成六边形（顶边展开到素材轮廓），末段淡出交接给带网点的正式底板、文字随后浮现，全程 20 帧；开场前预置首句名字，动画只播一次。 |
| **开发者面板** | 内置选择器 / 姿势 / 变量调试入口（`installDevPanel`）。详见[开发者面板](#开发者面板)。 |

## 场景数据格式

> 本节是剧情模式字段定义的**唯一权威出处**。示例见 `steins_gate/story/scenes/demo.json`。

一个场景可让多名角色同台。`cast.json` 先为每个角色绑定模型，场景用 `stage` 声明谁上场、站哪：

```json
{
  "title": "二人对话",
  "background": "background.jpg",
  "bgm": [
    { "file": "theme.mp3", "range": [1, 4] },
    { "file": "climax.mp3", "range": [5, 12] }
  ],
  "stage": [
    { "role": "红莉栖", "x": -0.35, "scale": 1, "z": 0 },
    { "role": "铃羽",   "x":  0.38, "scale": 1, "z": 1 }
  ],
  "lines": [
    { "role": "红莉栖", "text": "你来了。", "action": "平常", "exit": ["铃羽"] },
    { "role": "铃羽",   "text": "抱歉，我来晚了！", "enter": ["铃羽"] },
    { "role": "铃羽",   "text": "别站在门口，进来。", "action": "微笑",
      "cues": { "红莉栖": { "action": "惊讶" } } },
    { "role": "铃羽",   "text": "……我站这边就好。", "move": { "铃羽": -0.1 } },
    { "role": "铃羽",   "text": "先走了。", "exit": ["铃羽"] }
  ]
}
```

**字段速查**：

| 字段 | 位置 | 含义 |
|---|---|---|
| `title` / `background` | 场景 | 标题 / 背景图 |
| `bgm` | 场景 | 背景音乐段列表，可多段，见[下节](#背景音乐-bgm) |
| `stage` | 场景 | 本场默认登场角色与站位；可省略，见[登场阵容](#登场阵容-stage) |
| `role` | 行 | 这一句的说话者，`action` 取 `cast[role].actions`、`voice` 取 `cast[role].voiceDir` |
| `text` / `name` | 行 | 台词 / 对话框显示名，见[显示名](#站位与显示名) |
| `action` / `voice` | 行 | 说话者的动作宏 / 语音文件 |
| `enter` / `exit` | 行 | 本行中途上 / 下场的角色 |
| `move` | 行 | 本行站位调整，见[站位与显示名](#站位与显示名) |
| `cues` | 行 | 同台其他角色本行的演出，见[同台演出](#同台演出-cues) |
| `wait` | 行 | AUTO 推进时在本句语音之外额外停顿 |

### 背景音乐 bgm

`bgm` 可选、可多段。每段：

- `file`——`static/bgm/` 下的音频文件名。
- `range: [起, 止]`——1-based 闭区间句号，如 `[1,3]` 表示第 1 到第 3 句。曲子在该区间内循环，跨行不打断、不从头重播；进入下一段或离开区间才切换/停止。旧格式 `{ file, from, to }` 读取时自动迁移成 `range`。
- `fadeIn` / `fadeOut`（可选布尔，默认 `false`）——`fadeIn` 在开始播放时音量渐入，`fadeOut` 在停止或切段时渐出，均约 1 秒；试听和剧情播放都生效。

**编辑器操作**：属性面板列出 `static/bgm/` 的音频（可用搜索框按文件名过滤），拖到剧本行右侧的 BGM 竖轨即可落段。拖整段平移、拖上下边缘改长度，都按句号一格一格吸附。竖轨窄，段上的曲名竖排显示，底部小字是覆盖句号。点段落后在右侧面板配置起止句、播放试听、切换「淡入」「淡出」，或点删除；选中段后按 `Backspace` / `Delete` 也能删。编辑态不会自动播，播放模式仍按行自动切曲。

### 登场阵容 stage

`x` 为画布宽度比例（-1 左 / +1 右），`scale` 为相对缩放，`z` 为叠放次序——这是**本场默认站位**。台词里写过 `enter` 的角色算中途登场、开场隐藏，其余角色开场在台；之后谁在第几句上/下场由 `enter` / `exit` 决定。`stage` 可省略：此时按台词里出现的角色自动均分站位，旧剧本无需改动即可播放。

### 站位与显示名

`move` 是**本行的站位调整**：键是角色名，值是 `x` 数字或 `{ x, scale, z }`（只写要改的字段）。省略就沿用上一句，写了就一直生效到下一次调整——不必每句都重复位置。

`name` 是**这一句起对话框上显示的名字**。和 `move` 一样写一次就沿用，直到同一角色下一次改写；省略＝沿用上一句。用来做「？？？」这类未知称呼——`role` 照样写角色键名，模型、语音、站位、动作全都不受影响：

```json
{ "role": "红莉栖", "text": "你是谁？为什么会知道我的名字。", "name": "？？？" },
{ "role": "红莉栖", "text": "别用那种眼神看着我。" },
{ "role": "红莉栖", "text": "……算了，我是牧濑红莉栖。", "name": "红莉栖" }
```

名字的默认值在 `cast.json` 里：`{ "红莉栖": { "model": "…", "name": "助手" } }`，不写就用键名。键名是内部 id（剧本、语音目录、模型绑定都挂在它上面），显示名只影响对话框上的字，改它不会断任何引用。编辑器里分两层：选中某行后的「显示名」是**这一句起**的称呼（留空＝沿用，`⟲` 填入角色本名用来「揭示真名」，旁边的「设默认」把它写成角色默认名）；角色表页签的「显示名」是**全局默认**。

### 同台演出 cues

`cues` 是**同台其他角色本行各自的演出**，写法与行级相同（`action` / `voice` 都可省略）：

```json
"cues": {
  "红莉栖": { "action": "惊讶", "voice": "resg00_01_krs0005.xwma.opus" },
  "铃羽":   { "action": { "timeline": "表情_笑う", "diffSlot1": "ひく", "diffSlot2": "" } }
}
```

动作对象只有三个字段：`timeline`（主时间线）、`diffSlot1` / `diffSlot2`（两条独立差分槽）。省略某个字段＝不动它，写空串＝显式清空（比如上一句挂过 `diffSlot2`，这一句要卸掉）。

每个角色一台音频播放器，语音与口型只落在自己身上，两人同时开口也不会互相打断。

### 自动推进

自动推进不写在台词里：对话框上的 `AUTO`（用 `main.psb.m` 里的原生切片，位置照游戏在对话框左下角，`left:26 / top:1022`）是全局开关。亮起后每句等说话者的语音放完（再加本行 `wait`）自动翻页，点击画面可立即继续；开关状态记在 localStorage 里，刷新后保持。台词里旧数据的 `auto` 字段已废弃，读取时忽略、保存时自动清掉。

### 眨眼 blink

节奏不自己排，跟 wasm 自带的自动眨眼走——每 1.3–3s 沿 10 帧曲线把 `face_eye_open` 抬到 `10`（閉じ）再落回基线。

配置在**角色级**：`cast.json` 的 `blink`（`on` 缺省 `true`，`closeValue` 缺省 `10`；`vars` / `track` 可换变量名），角色表顶部一行「<角色> 默认眨眼」直接读写。**动作不再单独覆盖**，所有动作都跟随角色这一套设置。眨眼在站位落定后给**全员**起表，不用等谁开口。翻页 / 换场 / 结局 / 进编辑模式会停表并把 diff 归零。

<details>
<summary><b>眨眼的内部机制（想深入理解时展开）</b></summary>

**变量组合按模型自适应**：`face_eye_open_l` / `_r` 才是眼皮线（`0` 睁 / `5` 半闭 / `10` 全闭 / `55` 特殊），而 SDK 只驱动单数 `face_eye_open`（眼内阴影 / 瞳线 / 高光），所以真正闭眼要靠我们补 L/R；模型没声明这两个变量的（只有 `face_eye_open`），一个都不写——那种模型 SDK 自己就把眼皮推到位了，写了就是双倍闭合。

**驱动方式**：用 `setVariableDiff`（module `blink`）。diff 会叠加在当前基准上并进渲染（实测 lid `0` + diff `15` 与 lid `10` 的画面一致），所以动作正在渐变、dev panel 手动调表情都不必避让；停手时把 diff 写回 `0`，基准自己就露出来。每帧只做一次线性跟随：

```
k    = (track - trBase) / (10 - trBase)
diff = (closeValue - 眼皮实时值) * k
```

两个细节是关键：

1. **相对基线**——`face_eye_open` 的静止值会被表情抬高（鈴羽「生气」= `2`、紅莉栖「吃惊」= `8`），拿绝对值当比例会常驻半闭、眨眼只剩 2 个单位的行程（看起来「只眨一点点」）。基线按**变化速率**认：慢于 `0.015` 单位/ms 的位移算表情渐变（吃惊 8 个单位 / 1 秒 = `0.008`），直接跟着走；快变（眨眼 `0.02~0.12`）之后 250ms 内不认漂移，免得眨眼到峰值稍一停顿就把峰值当成基线而「睁一下再闭」。这与帧率无关，低帧率下也不会误判。
2. **补到 close 的差量而不是加一个 close**——眼皮基准不是 0（吃惊 `-5`、生气 `4`），直接 +`closeValue` 会闭不满或闭过头（`4+10=14` 早就越界）。

**兜底**：`track` 顶在满闭超过 250ms 还不落，就不是眨眼而是动作把眼睛压住了（鈴羽「摇头」的困る01 会把 `face_eye_open` 一直顶在 `10`），此时改认基线、diff 归零，不再强行闭眼——否则那句之后一直闭着，重播也带着。

diff 常驻没有 remove 接口，停表 / 换掉眼皮变量 / 关眨眼 / 换动作都必须显式写 `0`。

</details>

## 编辑器操作

- **右面板按「一句一行」组织**：`场景` → `第 N 行`。行号只出现一次——说话者、显示名、文本、AUTO 停顿，以及这一句的**登台角色**都在同一个「第 N 行」区块里（`登台角色` 是行内小标题，不再单开一节）。`cast.json` 不再占右面板的位置。
- **「登台角色」一张卡就是一个角色**，四排写完它在这一句里的全部事情：

  1. 角色下拉（这一场有谁）＋ `不变 / 登场 / 退场`（这一句的上/下场，写进该行 `enter`/`exit`）＋ 移除；
  2. 位置与缩放（**第 1 行写的就是全场默认**存进 `stage`，第 2 行以后改动才生成该行 `move`，不写就沿用；灰色＝沿用，`↺` 退回沿用，橙色＝本行覆盖）；
  3. 本行动作与语音（说话者写行级 `action`/`voice`，其他角色写该行 `cues`；选「自定义…」就地展开 **主时间线 / 差分槽 1 / 差分槽 2** 三个下拉，填个名字点「存为宏」就写进 `cast[role].actions`）；
  4. **绑定**：默认收成一行摘要（`绑定 牧瀬紅莉栖ab_白衣 ▸`），点开才是模型下拉与语音目录——「这个角色用哪套皮、声音在哪」就放在角色自己身上。

  三个下拉都直接列出该角色模型的标签，选错了随时改选，不必先清空；空值＝不改（差分槽写空＝显式清空）。不再有独立的「站位」「本行演出」区块——一个角色在哪、这一句演什么、用的哪套模型，都在它自己那张卡里。

- **显示名随处可见**：行列表的角色名、说话者下拉、角色卡下拉都按 `cast` 里的显示名显示（有自定义名时带 `（内部 id）`，重名也分得开），本行「显示名」的 `沿用：X` 提示也即时跟着变。想给角色起名不必离开这一行。
- **左栏两个页签**：`剧本` / `角色表`，同一块区域切换；`Esc` 从角色表退回剧本。角色表把右面板让出来，按 `角色 / 动作宏 / 属性` 三栏铺满，用于全景核对、重命名与删除；宏列表每行直接给出主时间线。日常的模型、默认名、宏仍在使用现场（角色卡、行内「设默认」、「存为宏」）就地改，不必特意来这一页。
- **只有一个「保存」**：场景与 `cast.json` 一次写完（`saveCurrent` 会同时 PUT 两个文件）。角色表里没有自己的保存按钮。
- **变量从舞台搬到剧本**：在 LAB 页「变量微调」里调好一组值后点「复制参数」（导出非零的 `variables` JSON），到角色表选中某个动作宏 → 属性栏「变量 variables」点「粘贴导入」，即可批量追加为变量行。变量名是下拉框，选项来自当前角色模型的 `variableList`；旧配置和粘贴导入的未知名会作为一个选项直接显示；要写全新的名字就选「自定义…」，回车或点别处确认后自动变回下拉，`Esc` 取消；`value` / `duration` / `delay` 仍是数字输入，`Ctrl+Enter` 快速导入。这样一个动作宏就能带上调好的差分/表情变量。
- 切换场景时若需要新的模型会整页重载一次；在角色卡里换模型会明确提示「保存后刷新页面生效」。

### 开发者面板

LAB 页内置的选择器 / 姿势 / 变量调试入口（`installDevPanel`）：

- **③ 变量微调**——「复制参数」按钮把当前滑杆值导出成 `variables` 数组 JSON（`[{name,value,duration}, ...]`），**自动跳过 `value=0` 的项**（0 是复位态，粘进动作没有意义），全为 0 时提示「无非零值」。滑杆区间按变量的真实 `minValue / maxValue` 走（`face_eye_open_l` 是 `-10 ~ 55`，不是写死的 0~100）。
- **④ 变量帧别名**——把官方 `variableList[].frameList` 摊开：每个变量按区间分组，帧名做成按钮（如 `閉じ 10`），点一下直接取值、当前命中帧高亮；顶部搜索框可按帧名过滤（输入「閉じ」会筛出所有带该帧的变量并自动展开）。这些帧名在模型里本来就存在，只是之前没有界面显示。

## 技术要点

### 为什么自己解析 PSB

wasm 导出了 84 个 `EmotePlayer_*` / `EmoteDevice_*` 函数，`emoteplayer.js` 实际调用其中 67 个。这些接口在模型元数据方面**只提供 `charaProfile` 标签与 `charaBounds`，不暴露图集矩形、`source` 表与 `customSelectorList`**。互斥手臂在 SDK 层无法枚举，只能在字节层面读出来——这是 `PsbReader` 存在的唯一理由。

解析器只读结构区（约 1 MB），跳过其后约 200 MB 的贴图数据，浏览器内耗时约 10 ms。

### 为什么在纹理层打补丁

运行时的 wasm 为 3.9.8，不理解 PSB 4.0 的 `insert` / `delete` 语义，会把 A / C 两套手臂全部绘制。改为在 `texImage2D` 上传 atlas 时，把未选中那套手臂的矩形擦成透明，SDK 侧无需任何修改。

## 已知限制

- 仅支持未加密、未压缩的 PSB v4 `pure.psb`。遇到 MDF / PSZ 加密壳、PSB v3 或其他平台导出，需要扩展头部与壳处理。
- 依赖 3.9.8 运行时；未来 SDK 版本行为变化可能影响纹理补丁的假设。
- 触摸命中区依赖模型自身的 `charaProfile`，缺失时降级为无反应。
- 缩略图按原图文件名存放（`static/background/.thumbs/<原名>.jpg`），用同名新图替换原图后旧缩略图不会自动失效，删掉对应文件即可重新生成。
