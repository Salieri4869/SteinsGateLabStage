# 动作配置指南

> 给某个模型定制触摸反应、表情、差分与语音时看这一篇。**只改 JSON，不改任何 JS，也不需要构建步骤。**
> 模型、背景、语音等素材需从你合法持有的游戏副本中取得，本仓库不附带这些资源。

---

## 1. 为什么是「一个模型一份配置」

E-mote 模型之间没有统一命名：

| 模型 | 「惊」时间线 | 变量名 | 特有部位 |
|---|---|---|---|
| 牧瀬紅莉栖 `ab_白衣` | `表情_驚き00` | `face_eye_open_l` / `_r` | `bust` |
| 巧可拉 `chocola-koneko` | `驚き00` / `びっくり` | `face_eye_open`（单数） | `QQ` |
| 夏野浴衣 `yuk_6` | `驚きＡ` | 同上略有差异 | 没有 `bust` |

写死一套名字，换个模型就会「一半会动、一半静默失效」。所以配置以**造型文件**为单位：一份 JSON 描述一个模型的完整演出。

注意：**不能按角色文件夹共享**。实测同一个 `牧瀬紅莉栖/` 里，`ab_白衣` 是 42 条主时间线 / 59 条差分，`c` 却是 31 / 45，连 `表情_驚き00` 都换成了 `表情_驚く`。按文件夹做键一定会错，按造型文件名才准。

## 2. 目录与命名：镜像 `data/`

```
steins-gate-lab-stage/
├─ data/
│   └─ <角色文件夹>/<模型文件>.zip | .psb
└─ actions-config/
    ├─ common.json                 ← 公共 base，必须存在
    └─ <角色文件夹>/<模型名>.json   ← 专属配置，可以没有
```

文件名由 `stripModelExt()` 推导：去掉 `.zip`，再按由长到短剥掉 `.psb.m.pure.psb` / `.psb.m.pure` / `.psb.m.psb` / `.pure.psb` / `.psb.m` / `.psb` / `.pure`，剩下的部分加 `.json`。

| `data/` 里的模型 | 对应的配置文件 |
|---|---|
| `data/牧瀬紅莉栖/牧瀬紅莉栖ab_白衣.psb.m.pure.zip` | `actions-config/牧瀬紅莉栖/牧瀬紅莉栖ab_白衣.json` |
| `data/巧克力/chocola-koneko.pure.psb.zip` | `actions-config/巧克力/chocola-koneko.json` |
| `data/新建文件夹/ナビ娘_立.psb` | `actions-config/新建文件夹/ナビ娘_立.json` |

- 中文 / 日文路径会自动做 URL 编码，不用改成英文。
- **不需要索引文件、注册表或 manifest**：程序按当前模型路径直接推导并读取那一个 JSON，因此也不依赖服务器返回目录列表。
- 专属 JSON 返回 404 是**正常情况**，意思是「这个模型没写专属配置」，自动回退 `common.json`。

## 3. 加载顺序与继承

```
resolveModelUrl()                  决定当前模型
   ↓
并行 fetch  common.json + 专属 JSON
   ↓
validateActionsConfig()            结构 / 复位来源校验
   ↓
ModelLoader.attach()               此时才有模型的真实清单
   ↓
reconcile()                        把配置里的名字对齐到当前模型（第 6 节）
   ↓
InteractionManager                 开始响应点击
```

**来源判定**

- `source = own`：专属文件存在 → `common.json` 与它做稀疏合并；
- `source = common`：专属文件不存在 → 只用 `common.json`；
- 两个文件都读不到 → 页面明确弹窗报错，不再静默套用旧配置。

**稀疏继承规则**

- 对象递归合并，**数组整体替换**（`pool` / `variables` / `defaultState.variables` 不会拼接）。
- `extends` 默认是 `common.json`；也可以写**同目录**的另一个 JSON 文件名，让同角色的造型共用一套演出。仓库里 `牧瀬紅莉栖/牧瀬紅莉栖ab.json` 就只有一行 `extends`，继承 `牧瀬紅莉栖ab_白衣.json`，因此默认模型仍有红莉栖语音。
- `extends` 只支持一层、只允许同目录文件名，带 `/`、`\`、自引用都会被忽略并退回 `common.json`。
- `doc` / `extends` / `model` 是元字段，合并时会被剥离，不进入生效配置。

**语音隔离**：`audio` **只在专属配置里写才生效**。`source = common` 时会把 `audio` 全部清掉，所以巧可拉不会突然开口讲红莉栖的台词。语音路径相对播放页 `steins_gate/index.html`，例如 `../sounds/krs/xxx.opus`。

## 4. 字段速查

| 字段 | 位置 | 类型 | 说明 |
|---|---|---|---|
| `doc` | 顶层 | string | 给自己看的说明，不生效 |
| `extends` | 顶层 | string | `common.json` 或同目录文件名 |
| `model` | 顶层 | string | 备注对应的模型文件名，不生效 |
| `debug` | 顶层 | boolean | 默认 `true`；为 `true` 时 `window.player` 可查清单 |
| `reactions` | 顶层 | object | key **必须**是该模型 `charaProfile` 里的真实 marker 名 |
| `reactions.<marker>.radius` | 部位 | number > 0 | 命中半径 = 画布显示高度 × 该比例，如 `0.06` |
| `reactions.<marker>.pool` | 部位 | array | 动作池，点击时随机抽一条 |
| `timeline` | 动作 | string | 主时间线名，取自 `player.mainTimelineLabels` |
| `diffSlot1` / `diffSlot2` | 动作 | string | 差分槽名，取自 `player.diffTimelineLabels`；`""` 表示清空 |
| `variables[]` | 动作 | `{name, value, duration, delay?}` | 变量插值，`duration` / `delay` 单位 ms |
| `duration` | 动作 | number | 保持时长 ms；实际保持 `max(duration, 语音时长, 1000)` |
| `audio` | 动作 | string | 语音相对路径，仅专属配置生效 |
| `recovery[]` | 动作 | `{name, value, duration}` | 动作结束后覆盖式复位 |
| `defaultState` | 顶层 | object | 全局复位：`timeline` / `diffSlot1` / `diffSlot2` / `variables[]` |

几个容易忽略的点：

- 命中区重叠时，按 `dist / radius` 归一化取最小，不是按配置顺序，所以 `eye` 与 `mouth` 谁先写都不影响。
- `recovery` 支持三个特殊名：`__timeline`、`__diffSlot1`、`__diffSlot2`，用来单独复位时间线与差分槽（它们的 `value` 是字符串）。
- 校验器（`steins_gate/config-validator.js`）会拒绝：`reactions` 写成数组、部位里写 `marker` 字段、`radius` 非正数、`pool` 不是数组、使用虚拟部位（`eye_left` / `eye_right` / `bust_left` / `bust_right` / `belly`）、`debug` 非布尔。**每个动作里用到的变量，必须能在 `defaultState.variables` 或本动作 `recovery` 里找到同名复位项**，否则 E-mote 变量会「卡脸」。

## 5. 给新模型写一份配置

### 第 1 步：放模型

把模型放进 `data/<角色文件夹>/`。刷新 LAB 页，角色 tab 会自动出现新造型（模型发现依赖本地 HTTP 服务的目录列表；若服务不返回目录列表，用面板的「导入文件夹」兜底）。

### 第 2 步：查这个模型的真实清单

打开 LAB 页的浏览器控制台（`common.json` 里 `debug: true`，所以 `window.player` 已挂出）：

```js
Object.keys(window.player.charaProfile)   // 可用 marker（reactions 的 key）
window.player.mainTimelineLabels          // 主时间线
window.player.diffTimelineLabels          // 差分时间线（差分槽）
window.player.variableList                // 变量名

window.SGActionsConfigLoad                // 推导出的配置路径、来源、extends 是否命中
window.SGConfigInfo                       // 库存对齐后的生效摘要
```

照抄清单里的名字，不要凭别的模型猜。若看到大量 `sample_*` 或 `-----<表情セット>-----` 之类的调试段，跳过它们。

### 第 3 步：建 JSON

在 `actions-config/<角色文件夹>/` 下按第 2 节的命名规则新建文件。最省事的骨架：

```json
{
  "doc": "我的模型",
  "extends": "common.json",
  "reactions": {}
}
```

只写要改的字段即可，其余全部继承 `common.json`。

### 第 4 步：填一个部位

下面这份可直接复制修改（名字取自巧可拉的真实清单，换成你自己模型的）：

```json
{
  "doc": "示例：只给眼睛加一个惊吓反应",
  "extends": "common.json",
  "model": "my-model.pure.psb.zip",
  "reactions": {
    "eye": {
      "pool": [
        {
          "timeline": "驚き00",
          "diffSlot1": "悩み",
          "diffSlot2": "",
          "duration": 1200,
          "variables": [
            { "name": "face_eye_open", "value": 30, "duration": 500 }
          ],
          "recovery": [
            { "name": "face_eye_open", "value": 0, "duration": 300 }
          ]
        }
      ]
    }
  }
}
```

这里没写 `radius`，会继承公共配置里 `eye` 的 `0.06`；`mouth` / `bust` / `top` 等其它部位也照常继承。想整块覆盖某个部位，就在专属文件里重新给它一个 `pool`；想彻底关掉某个部位，把它的 `pool` 写成 `[]`。

### 第 5 步：校验 + 刷新

```bash
# 在项目根目录执行
node steins_gate/config-validator.js
```

它会遍历 `actions-config/` 下所有 JSON，按运行时的 `common + extends` 规则合并后逐份校验，失败会指出具体文件与字段。请求用了 `no-store`，所以改完**刷新页面即可生效**，不用清缓存、不用重启服务。控制台出现 `[ActionsConfig] 来源=own ...` 就说明专属配置被读到了。

## 6. 写错名字会发生什么（库存对齐）

模型加载完成后，`reconcile()` 会拿真实清单逐项比对，并把结果写进 `window.SGConfigInfo`：

| 引用 | 当前模型里不存在时 |
|---|---|
| `timeline` | 词干归一化（NFKC、去 `表情_` / `sample_` 前缀、去编号与全半角字母后缀）+ 精简意图词典，求解成同类真实名字；无解则删掉该 `timeline`，变量仍照常执行 |
| `diffSlot1` / `diffSlot2` | 置空 |
| 变量名 | 剔除该条 |
| marker（部位 key） | 整个部位删除 |
| `defaultState.timeline` | 兜到当前模型的中性表情（`普通` / `平常` / `待機` …） |
| 动作池被清空 | 该部位删除 |

摘要字段：`source`、`neutral`、`defaultTimeline`、`effectiveParts`、`resolvedTimelines`、`removedParts`、`clearedDiffs`、`clearedAudio`、`warnings`。

所以「没有专属配置的模型」不是不能动：它会走公共配置、自动把 `表情_驚き00` 之类求解成 `驚きＡ` / `びっくり`，代价是没有专属语音、动作组合也是通用的。想要精确演出，就给它写一份 JSON。

一个特例：某模型 0 个 marker、时间线全是 `sample_*`（仓库里的成瀬乃々就是这样），会被判为**无交互能力**，部位全部剔除，这是预期行为。

## 7. 排错表

| 现象 | 原因与处理 |
|---|---|
| 点了完全没反应 | 看 `window.SGActionsConfigLoad.ownUrl` 是不是你要的路径（多半是文件名没剥干净后缀）；再看 `SGConfigInfo.removedParts` 是否被剔了部位 |
| 网络里专属 JSON 是 404 | 正常，说明文件不存在、已回退公共配置；按第 2 节把文件放对位置 |
| 语音不播 | `audio` 写在了 `common.json`，或当前 `source = common`；语音只能写在专属配置里，并确认路径相对 `steins_gate/index.html` |
| 动作「一半动、一半不动」 | 时间线名属于另一套模板；按第 5 步查清单照抄，或依赖库存对齐自动求解 |
| 弹「动作配置缺失」 | `common.json` 和专属文件都没读到；确认用 HTTP 打开（不支持 `file://`）、目录名与大小写一致 |
| 改了 JSON 没变化 | 刷新页面即可；若自己的服务器强制缓存，强刷一次 |
| 校验器报「变量无法复位」 | 在 `defaultState.variables` 或该动作的 `recovery` 里补一条同名项 |
| `extends` 没生效 | 只允许一层、同目录文件名，不能带路径分隔符或指向自己 |
| 控制台有「剔除部位」警告 | 该模型没有这个 marker（如夏野浴衣没有 `bust`），属正常降级 |

## 8. 设计约束

- **不扫描整个配置目录**：路径可由模型名机械推导，启动时只读取当前模型那一份，不依赖 HTTP 目录索引，也不会产生上百次请求。
- **配置和美术资源分目录**：`actions-config/` 可以单独进版本库、单独 diff；`data/` 保持只有模型文件。
- **专属配置是可选的**：稀疏继承 + 库存对齐让新模型「零配置也能动」，按模型单独配置则是想精修时才做。
- **配置里的名字必须来自模型自身**：程序只在写错时做同类求解，不保证还原成你心里那一个具体名字；精确演出靠手写 JSON。

相关代码：`steins_gate/actions-config-loader.js`（路径推导、继承、库存对齐）、`steins_gate/config-validator.js`（结构与复位校验）、`steins_gate/main.js`（`InteractionManager` 消费这些字段）。
