# 互斥选项自动切换 · 使用说明

> **适用**：`steins_gate/` 页面（E-mote WebGL SDK 3.9.8）
> **一句话**：模型按 4.0 的「动态插入 / 删除部件」制作，3.9.8 不认识这套指令，把本该互斥的几套部件同时画出来。本页面在贴图上传到显卡时，把当前没选中的那套擦成透明。
> **想了解原理与判据**：见同目录《手臂姿势修复技术路线.md》

> **In English** — Usage guide for the exclusive-option switcher described in the technical write-up. The model
> zip is the only input: `model-loader.js` reads the PSB v4 structure region and derives which selectors exist,
> which options each has, and which atlas rectangles every option owns; `gl-arm-pose.js` hooks `texImage2D` and
> patches those rectangles in the GPU texture, so switching an option never reloads the model. Control surface:
> `setOption(selector, option)` and `setArmPose(name)` globally, `window.ArmPoseGL` for low-level access, and a
> `SelectorAPI` shim that also accepts the original `setVariable()` signature plus a timeline bridge that syncs
> selector values written by the model's own diff timelines. A dev panel exposes selectors, native diffs,
> variables, timelines and the parts inventory. Swapping models = drop a new zip into `data/` and point one
> constant at it.

## 解决的是什么

| 模型 | 症状 | 修复后 |
|---|---|---|
| 牧瀬紅莉栖 | 两套手臂同时出现 → **4 个袖子** | 当前姿势只剩 2 个袖子 |
| 桐生萌郁 | 5 套手机拇指差分叠加 → **多个拇指叠影** | 每选项只剩 1 个拇指 / 手背形态 |
| 椎名まゆり | 互斥手臂 + 摇动层叠加 → 同侧两条前臂 | 每个状态 2 条完整手臂 + 2 只手掌 |

## 流程

```
模型 pure.zip
  → 解压成 Uint8Array（本来就要交给 SDK）
  → 从中读前 ~1 MB 结构区，识别互斥选择器 / 选项 / 各自的贴图矩形
  → texImage2D 上传 atlas 时就地备份这些矩形 + 按当前选项擦除
  → 正常渲染：只剩 1 套部件
  → 切换选项：texSubImage2D 重写这些矩形，结束
```

**唯一需要的输入就是模型 zip 本身。** 不需要反编译工具、不需要额外 JSON、不需要预生成配置、不需要构建脚本，也不用在代码里写死 `arm_type` / `yubi_type` 或选项数量。

## 代码结构

| 文件 | 作用 |
|---|---|
| `steins_gate/gl-arm-pose.js` | 纹理 hook 的全部逻辑，配置驱动、模型无关，暴露 `window.ArmPoseGL` |
| `steins_gate/model-loader.js` | 下载 / 解压 zip、解析 PSB 结构区、算配置、`SelectorAPI` 兼容层、交给 SDK；Node 侧可 `require()` 做回归 |
| `steins_gate/index.html` | 引入顺序：`gl-arm-pose.js` 必须是第一个脚本，`model-loader.js` 排在所有业务脚本之前 |
| `steins_gate/main.js` | 默认选项；右侧「差分控制」侧面板默认收起；全局 API |
| `driver/` 的 wasm、`emoteplayer.js`、模型文件 | **一行未改** |

核心补丁链路只涉及 `gl-arm-pose.js` + `model-loader.js` 两个文件；`main.js` 负责入口与面板。

## 怎么用

```js
// 推荐：直接用模型自己的选项名（面板按钮标签也是它）
await setOption('arm_type', 'arm_c');
await setOption('yubi_type', 'fade_yubi_c');

// 兼容别名：只对 2 选项的组成立，且是纯位置映射
//   crossed → 第 2 个选项    hanging → 第 1 个选项
// 具体是「抱臂」还是「抬起」由模型决定，不要跨模型假设
await setArmPose('crossed');
await setArmPose('hanging');

getArmPose();        // 当前选项名；没有互斥组的模型返回 null
getSelectors();      // [{ label: 'yubi_type', options: [...] }]
getPoseList();       // [{ name, label }]，面板按它生成
openDevPanel();      // 展开侧面板（closeDevPanel / toggleDevPanel / getDevPanel 同理）
```

> `setArmPose()` 只接受 `getPoseList()` 里列出的名字（2 选项模型即 `crossed` / `hanging`，其它组则是选项原名）。想按原始选项名切换，用 `setOption(selector, option)`。

诊断：

```js
ArmPoseGL.info();                 // supported / configured / disabled / uploads / records / applyCount / errors
ModelLoader.getPoseConfigInfo();  // 配置来源与解析耗时
```

`ArmPoseGL.setPose()` 同步返回 `{ pose, state, atlases, ms, ready }`；`atlases` 是本次实际重写的贴图数，`ready` 表示所有应贴的矩形都已按当前状态贴好。

## 侧边控制台（默认收起）

页面右侧只露一个竖标签「差分控制」，点击滑出宽约 340px 的面板；再点标签、点「收起」或按 `Esc` 收回。**默认收起**，不遮挡角色。

面板按模型自身数据动态生成，分五区：

| 区 | 内容 | 控制方式 |
|---|---|---|
| ① 互斥部件 · GPU 补丁 | 自动识别的互斥组，**按选择器分行**（`arm_type` 2 个按钮 / `yubi_type` 5 个按钮） | `setOption` → `SelectorAPI.setSelector` → GPU |
| ② 原生差分 · 3.9.8 | 其余 `customSelectorList` 组（`head_type` / `body_type` / `eye_type` / `eyebrow_type` / `mouth_type` …） | 选中项写 `onValue`、其它项写 `offValue` |
| ③ 变量微调 | 3.9.8 认识的全部变量滑杆 0–100（每模型 32 个），互斥组变量已排除 | `setVariable(label, value)` |
| ④ 时间线 | 全部主时间线 + 差分槽 1/2 下拉（白衣 101 条 / 桐生 79 条） | `mainTimelineLabel` / `diffTimelineSlot*` |
| ⑤ 部件清单 | 全部 `customPartsList` 部件（白衣 138 / 桐生 81），显示 id、名称、变量锚点，带搜索 | 只读 |

底部「恢复默认差分」把互斥组与原生组拨回第一项。面板内 `pointerdown` / `click` 阻止冒泡，避免误触发角色点击 / 拖拽。

按钮标签一律用**模型自己的选项名**（`arm_a` / `arm_c` / `hat` / `hat_re`），不套「抱臂 / 垂手」这类只在某一个模型上成立的自造语义；`crossed` / `hanging` 仅作为旧 API 的兼容别名保留。

> 三个数据源：模型 zip 的 PSB 结构区（选择器 + 部件清单，惰性解析约 10 ms）、GPU 补丁状态机（哪组被接管）、SDK 自己的 `variableList` / 时间线列表。换模型不用改代码。
> 部件清单是**只读**：3.9.8 没有部件显隐接口，逐个擦贴图矩形容易破坏共享图块。

## 3.9.8 有没有控制 customSelectorList 的函数？

**没有。** `iemote.h` 的公开接口只有 `SetVariable(const char*, float)` / `GetVariable(float)`、时间线、坐标缩放等，没有 selector、customParts、extension 的任何概念；`emoteplayer.js` 的 `setVariable(label, value, ms, easing)` 只能写**数值**变量。4.0 的 `customSelectorList` 在 3.9.8 里只被当成一个数值变量存下来，追加部件不会跟着显隐 —— 实测对 `yubi_type` 调 `setVariable` 画面逐像素不变。

所以 `model-loader.js` 内联了一层 `SelectorAPI`，在 `attach()` 时**只在 player 实例上包一层**（driver 一行不改），提供和 `setVariable` 同款签名的控制函数：

```js
// 显式的选择器 API
player.setSelector('yubi_type', 'fade_yubi_c');  // 返回 'fade_yubi_c'；也接受索引 2 / 简写 'c'
player.getSelector('yubi_type');                 // 'fade_yubi_c'
player.getSelectorIndex('yubi_type');            // 2
player.getSelectors();                           // [{ label, options, option, index }]
player.countSelectors();                         // 1
player.getSelectorLabelAt(0);                    // 'yubi_type'
player.getSelectorOptions('yubi_type');          // ['fade_yubi_a', …, 'fade_yubi_e']

// 兼容写法：原来的 setVariable 现在也能控制选择器
player.setVariable('yubi_type', 'fade_yubi_c');  // 字符串选项名
player.setVariable('yubi_type', 2);              // 或 0-based 索引
player.getVariable('yubi_type');                 // -> 2（当前选项索引）

// 普通 3.9.8 部位完全不受影响，仍走原生
player.setVariable('fade_eye_type_a', 100, 300);

// 控制台短别名；需要时恢复原生方法
setSelector('yubi_type', 'fade_yubi_e');
getSelector('yubi_type');
window.EmoteSelector.uninstall();
```

几条规则：

- 数字按**选项索引**（`0..n-1`）解释；`0..100` 这类原生 fade 数值保持 3.9.8 旧语义原样透传，避免动作配置被误当成选项切换。
- 切换时把**索引值**同步写回 wasm 的同名变量（不写 `fade_*` 底层变量，避免叠影），因此差分时间线也能驱动它。
- `ms / easing` 仅为对齐调用签名保留，切换即时生效（3.9.8 没有互斥选项过渡动画）。
- 没有互斥组的模型：`countSelectors()` 为 0、`setSelector()` 抛明确错误、所有 `setVariable()` 都走原生。

### 差分时间线也能驱动手指

模型自带的差分时间线若只写一个选择器变量（桐生「携帯入力」写 `yubi_type=1..4`、「携帯入力終了」写 0），3.9.8 只会把这个数存下来，不会展开成 `fade_yubi_*` 的互斥显隐，所以原生播放时手指不动。

`SelectorAPI` 内置「时间线桥」：逐帧读 wasm 里的选择器变量，值一变就同步到 GPU 状态。**在侧面板 ④ 时间线 → 差分槽 1/2 选「携帯入力」即可生效**，① 区按钮高亮也会跟着跳；选「携帯入力終了」回到第一项。

```js
EmoteSelector.disableTimelineBridge();
EmoteSelector.enableTimelineBridge();
EmoteSelector.timelineBridgeInfo();   // { enabled, ticks, syncCount, changes }
```

只有确实在写选择器变量的时间线会受影响。其它差分时间线（表情 / 仕草 / 移动）和没有这类时间线的模型（如紅莉栖 `arm_type`）完全不受影响，默认选项不会被覆盖；手动点 ① 区按钮也不会被桥拉回。

## 模型有多个互斥组时

有的模型不止一组互斥追加部件，例如椎名まゆり同时有 `hat_type`（帽子）和 `arm_type`（手臂）：

- 侧面板 ① 区**按选择器分行**，每组一行，按钮用模型自己的选项名。
- 默认选项绑定在名称含 `arm` / `腕` 的那组上，不会误切到帽子。
- `腕切替AC / CA`、`腕差分A / C` 这类只写索引变量的差分时间线，在下拉里选就能驱动切换；手动点过按钮之后再播时间线也能正确同步。

## 同一侧多出一条手臂时

有些模型除了互斥追加部件，还有一层「摇动 / 变形层」：两套手臂各自带一整条前臂，画在 PSB 的 `object` 树里而不在 `customPartsList` 中。3.9.8 会把两层一起画出来，于是同一侧出现两条前臂。

加载模型时会自动检查：两个选项是否各有一套这样的运动层、其中一层是否为「纯手臂」（另一层同时挂着胸 / 裙等躯干部件）、这一层是否真的含整条手臂形状的细长贴图。命中后**把两套手臂分别并入各自的互斥选项组** —— 选中谁就显示谁的整套手臂。

结果是每侧只有一条**完整**手臂：C 状态双手抓衣领，A 状态两条手臂自然下垂、手掌连在前臂末端；袖子、躯干、帽子都完整，无破洞、无孤立飘着的手掌。判据细节见技术路线 §2.4 ④。

## 换一个模型

把新的 `pure.zip` 放进 `data/`，改 `main.js` 里的 `MODEL_PSB` 指向它。**就这一步。**

选择器名、选项数、矩形、按钮文字全部自动适配。模型若根本没有任何互斥追加部件组，页面会跳过补丁、正常显示且不显示切换按钮。

> 一处保留的启发式：2 选项组在挑「主题顶层根」时仍用 `arm` / `腕` 字样排除「胴体 / 大衣」那棵顶层树（擦它会破图）；找不到时改用逐部件可见性传播。>2 选项组不需要这个提示。

## 两个注意点

- `gl-arm-pose.js` 必须是 `index.html` 里第一个脚本；`model-loader.js` 必须在 `main.js` 等业务脚本之前。
- 初始选项要在 `loadData()` 之前设定，否则首帧可能短暂出现多余部件。

## 效果与代价

- 只用**一份原始模型**，不生成第二份模型、不产生大体积副本。
- 读结构区约 **9 ms**、归组约 **3 ms**；相比 zip 下载与解压几乎可忽略，因此不需要缓存。
- 切换时**不重建播放器、不重新加载模型**，动画、物理、时间线保持连续；切回原选项截图逐字节一致，切换耗时 44–85 ms。
- 代价：依赖浏览器 WebGL；解析器针对未加密的 PSB v4 `pure.psb`；矩形像素备份约 31 MB 常驻内存。
