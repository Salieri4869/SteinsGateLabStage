## 🧩 Overview

Four entry points, each with a distinct role. The first three need the runtime and assets from [Quick start](#-quick-start).

| Entry | Purpose | Needs runtime |
|---|---|---|
| `index.html` | Character archive page (world intro + Labmem roster), pure static | No |
| `steins_gate/story/index.html` | **Story player**: typewriter, AUTO, voice, action cues | Yes |
| `steins_gate/edit/index.html` | **Editor workbench**: standalone page for writing scripts and arranging timelines | Yes |
| `steins_gate/stage/index.html` | **LAB player**: touch reactions, costume switching, lip sync, dev panel | Yes |

> 💡 The homepage has three in-page anchors — Works / Characters / Tech — plus entries to the story and LAB pages. Enter the workbench from "Edit ↗" on the story page. The editor and player each use their own wasm instance, so they do not interfere.

## 🚀 Quick start

> 🎯 Goal: from a blank command line to a character on screen in about 5 minutes (excluding SDK and asset downloads).

### 1. Install Node.js

```bash
node -v        # should print v18.x or higher
```

No output, or a version below 18? Download the **LTS build** from [nodejs.org](https://nodejs.org/en/download), install with the default options, **reopen your terminal**, then run the command above again.

> 💡 This project has zero dependencies — **no** `npm install`, and no `package.json`.

### 2. Get the code

```bash
git clone <your-repository-url>
cd steins-gate-lab-stage
```

### 3. Prepare the runtime (required)

Place the licensed E-mote SDK files as follows:

```
driver/
  emotedriver.js
  emotedriver.wasm      # verified against the driver_wasm_modularize build
  emoteplayer.js
```

- Apply at [M2 Co., Ltd. E-mote SDK](https://emote.mtwo.co.jp/).
- Check: all three files are visible under `driver/`.

> ⚠️ The SDK is proprietary software whose terms prohibit redistribution. **Never commit `driver/` to a public repository**; this project will not provide it.

### 4. Prepare assets (as needed)

Create these directories at the repository root and drop files in — file names are arbitrary, the page scans them automatically. All are excluded by `.gitignore` and must be supplied by you.

| Directory | Contents | Required | If missing |
|---|---|---|---|
| `character/data/<character>/<name>.pure.psb.zip` | Character models; each zip contains one `pure.psb` | Required to play | Character tab is empty |
| `static/background/` | Background images | Recommended | No background |
| `static/bgm/` | Background music | Optional | Music list is empty |
| `static/sfx/` | Sound effects | Optional | SFX list is empty (**never** falls back to BGM) |
| `character/sounds/` | Voice audio | Optional | Silent, playback unaffected |

> 💡 Extract assets from a copy of the game you legally own. Models appear automatically after a page refresh — no build step. Thumbnails in `.thumbs/` are generated by the page.

### 5. Start the server

| OS | Action | Notes |
|---|---|---|
| Windows | Double-click `run.bat` | Opens the browser; custom port: `run.bat 8901` |
| macOS / Linux / Git Bash | `./run.sh` | Opens the browser; custom port: `./run.sh 8901` |
| Any (manual) | `node main.mjs --port 8000` | Defaults to `127.0.0.1:8899`, does not open a browser |

Launcher scripts default to port **8000**; running `node main.mjs` directly defaults to **8899** — don't mix them up.

### 6. Verify

Open <http://127.0.0.1:8000/>. Seeing the character archive homepage means the server is up. Click "LAB" for the interactive models, or "Story" for script playback.

> ⚠️ Use HTTP. **Double-clicking `index.html` (`file://`) will fail**: browsers block `fetch` under `file://`.

### 7. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `run.bat` closes with "Node not found" | Node missing or not on PATH | Install LTS, reopen terminal, verify with `node -v` |
| "Port already in use" | Port 8000 is taken | Use another port: `run.bat 8901` / `./run.sh 8901` |
| Blank page, `fetch` errors in console | Opened via `file://` | Use `http://127.0.0.1:<port>/` |
| Character list is empty | Models in the wrong place | Check for zip files under `character/data/<character>/` |
| Models fail with a wasm error | Missing `driver/` files | Add the three files from step 3 |
| Saving a script fails | Static server is read-only | Use this project's `main.mjs`, which provides write endpoints |

## 🖥️ Local server and voice

`main.mjs` is a dependency-free static server (Node 18+, default port `8899`, bound to `127.0.0.1` only). Beyond `python -m http.server` it adds write endpoints:

| Endpoint | Purpose |
|---|---|
| `GET/PUT /api/order` | Read/write character order in `character/actions_config/order.json` |
| `GET /api/thumbs`, `PUT /api/thumb` | Background thumbnails in `static/background/.thumbs/` |
| `GET/PUT /api/story` | Read/write `steins_gate/edit/cast.json` and `steins_gate/edit/scenes/*.json` |
| `GET /api/voice` | List live-line audio (`steins_gate/story/voices/`) |
| `GET /api/voice?name=…` | Stream audio with Range support (seekable) |
| `POST /api/voice` (octet-stream) | Import audio, 12MB limit |
| `POST /api/voice` (json) | Text → speech synthesis (TTS hook) |

> 💡 The page's "Pick audio" and "Audio list" **do not use** write endpoints; they play in-browser only.

**Voice sources**

| Source | Behavior | Writes to disk |
|---|---|---|
| Pick audio | Select a local file, play via blob URL | No |
| Audio list | Play statically from `character/sounds/` | No |
| Text synthesis | Requires `EMOTE_TTS_BIN` (e.g. `edge-tts`) and optionally `EMOTE_TTS_VOICE` (default `zh-CN-XiaoxiaoNeural`); returns 501 when unconfigured | **Yes**, into `steins_gate/story/voices/` |

The external command must accept `--voice <name> --text <text> --write-media <file>`.

> 📌 Other static servers work for playback, but write access degrades to read-only: scripts cannot be saved, ordering lasts only for the session, only existing thumbnails are used, and TTS is unavailable. Both audio sources still work.

## ✨ Features

| Feature | Description |
|---|---|
| **Direct PSB reading** | Parses `.pure.psb` (PSB v4) directly — no decompilation, pre-generated config or build; models dropped into `character/data/` appear automatically |
| **Arm-pose switching** | Erases the unused PSB 4.0 exclusive arm set at GPU texture upload, compatible with the 3.9.8 runtime |
| **Touch reactions** | Hit areas from `charaProfile` labels, random action per hit, optionally with audio and variable interpolation |
| **Lip sync** | Offline WebAudio envelope analysis + rAF lookup driving `face_talk`; audio failures are reported and skipped |
| **Scene UI** | Character tabs, costume panel, background preview, tab reordering written back to `order.json` |
| **Story playback** | Typewriter, click / AUTO advance, voice, action macros; multiple characters on stage, mid-scene entrances/exits and blocking |
| **Editor workbench** | Standalone page for scripts and multi-track timelines (lines / BGM / SFX / voice / background), seamless edit↔play resume |
| **Dev panel** | Built-in selector / pose / variable inspector on the LAB page |

**Playback details**

- **Waiting gear**: after typing finishes, a spinning gear appears at the end of the line (37 frames baked from the original): the first 17 frames unfold, the next 20 loop. Hidden while AUTO is on.
- **Dialogue opening**: follows `MSGWIN.show` — white lines wipe in/out from both sides, window gradient wipes in, ending in the clean resting state.
- **Nameplate animation**: `show → deco_show → name` in strict sequence; side decorations light up from the center, the nameplate appears with a mesh deformation, the name fades in last.
- **Character cards**: one card per cast member. Switching roles makes the new role inherit all of the old role's behavior in the scene.

## 📖 Scene data format

> 📌 This section is the **single source of truth** for story fields. A working example lives at `steins_gate/edit/scenes/demo.json`.

A scene can keep several characters on stage. Bind roles to models in `cast.json`, then declare who appears and where with `stage`.

```json
{
  "title": "Two-person dialogue",
  "background": "background.jpg",
  "bgm": [
    { "file": "theme.mp3", "range": [1, 4] },
    { "file": "climax.mp3", "range": [5, 12] }
  ],
  "sfx": [
    { "file": "door.wav", "at": 2 }
  ],
  "stage": [
    { "role": "Kurisu", "x": -0.35, "scale": 1, "z": 0 },
    { "role": "Suzuha", "x":  0.38, "scale": 1, "z": 1 }
  ],
  "lines": [
    { "role": "Kurisu", "text": "You're here.", "action": "calm", "exit": ["Suzuha"] },
    { "role": "Suzuha", "text": "Sorry I'm late!", "enter": ["Suzuha"] },
    { "role": "Suzuha", "text": "Don't stand in the doorway, come in.", "action": "smile",
      "cues": { "Kurisu": { "action": "surprised" } } },
    { "role": "Suzuha", "text": "I'll stand over here.", "move": { "Suzuha": -0.1 } },
    { "role": "Suzuha", "text": "I'll go now.", "exit": ["Suzuha"] }
  ]
}
```

**Field reference**

| Field | Location | Meaning |
|---|---|---|
| `title` / `background` | scene | Title / background image |
| `bgm` | scene | Background-music segments — see [Background music](#background-music-bgm) |
| `sfx` | scene | Sound-effect segments — see [Sound effects](#sound-effects-sfx) |
| `fadeMs` | scene | Fade duration for entrances/exits and background changes (ms, default 300) |
| `stage` | scene | Default cast and blocking; optional — see [Casting](#casting-stage) |
| `role` | line | Speaker; empty `""` = narration (no nameplate, decorative lines still show) |
| `text` / `name` | line | Dialogue / name shown in the textbox |
| `action` / `voice` | line | Speaker's action macro / voice file |
| `enter` / `exit` | line | Roles entering / leaving mid-scene on this line |
| `move` | line | This line's blocking change |
| `cues` | line | Per-role performance for other on-stage characters |
| `wait` | line | Extra pause on top of the voice when auto-advancing |

### Background music bgm

`bgm` is optional and supports multiple segments:

- `file`: an audio filename under `static/bgm/`.
- `range: [from, to]`: 1-based inclusive line range; `[1,3]` covers lines 1–3. The track loops within the range without restarting on line changes.
- `fadeIn` / `fadeOut` (booleans, default `false`): ~1s fade in at start; fade out on stop or segment switch. Applies to both preview and playback.

> 🎛️ Editor: the properties panel lists `static/bgm/` audio (filterable); drag one onto the BGM vertical track to place a segment. Drag to move, drag its edges to resize — both snap to whole lines. Click a segment to edit its range, preview it, toggle fades, or delete it.

### Sound effects sfx

`sfx` is optional and follows a similar shape to `bgm`:

- `file`: an audio filename under `static/sfx/`.
- `at` (required), `to` (optional): 1-based inclusive line range; omitting `to` triggers a single line.

```json
"sfx": [
  { "file": "door.wav", "at": 2 },
  { "file": "alarm.wav", "at": 5, "to": 8 }
]
```

> ⚠️ If `static/sfx/` is empty, the SFX list is empty — it never falls back to BGM. They are not interchangeable.

### Casting stage

`x` is a fraction of canvas width (-1 left / +1 right), `y` a fraction of height (-1 down / +1 up, default 0), `scale` relative size, `z` stacking order — the scene's **default blocking**.

- A role with any `enter` starts hidden; other roles start on stage. Later entrances/exits are decided by `enter` / `exit` on each line.
- `stage` may be omitted: roles seen in the lines are spread evenly.

> 🎛️ Editor: "Cast on stage" shows one card per role. Switching roles makes the new role **inherit all of the old role's behavior** in the scene, with old references cleared. The second row has separate X / Y inputs for horizontal and vertical position.

### Entrance/exit fade

Scene-level `fadeMs` (number, milliseconds, **default 300**) sets the fade duration for entrances/exits and background changes. A line can override it:

```json
{ "title": "Night", "fadeMs": 600, "lines": [
  { "role": "Suzuha", "text": "Here I am.", "enter": ["Suzuha"] },
  { "role": "Kurisu", "text": "Hold on.", "fadeMs": 1200, "exit": ["Suzuha"] }
] }
```

Opacity is interpolated by the SDK's internal `_globalA`, costing no extra frames. Backgrounds are preloaded before cross-fading, so there is no black flash. Editing and replaying history snap to the final state; the first line appears with the dialogue-box opening rather than fading on its own.

### Blocking and display name

- `move`: this line's blocking change. Value is either an `x` number (horizontal only) or `{ x, y, scale, z }` (only the fields you want to change). Once set it holds until the next change — no need to repeat on every line.
- `name`: the name shown in the textbox from this line on. Also sticky until the same role overrides it. Omitting it inherits the previous line.

```json
{ "role": "Kurisu", "text": "Who are you?", "name": "???" },
{ "role": "Kurisu", "text": "Don't look at me like that." },
{ "role": "Kurisu", "text": "...Fine. I'm Makise Kurisu.", "name": "Kurisu" }
```

`name` in `cast.json` is the global default; without it the key is used. The key is the internal id (scripts, voice folders and model bindings all hang off it), so changing the display name breaks no references.

**Narration**: leave `role` empty — no nameplate, decorative lines still show, typewriter and AUTO work normally. Selecting "Narration" in the editor disables that line's display-name field.

### Cues

`cues` holds per-role performance for other on-stage characters on this line, written like line-level fields (`action` / `voice` both optional):

```json
"cues": {
  "Kurisu": { "action": "surprised", "voice": "resg00_01_krs0005.xwma.opus" },
  "Suzuha": { "action": { "timeline": "表情_笑う", "diffSlot1": "ひく", "diffSlot2": "" } }
}
```

An action object has exactly three fields: `timeline` (main timeline), `diffSlot1` / `diffSlot2` (two independent diff slots). Omit a field to leave it alone; an empty string clears it explicitly.

> 🔊 Each role has its own audio player, so lip sync and playback stay on that character and two people can talk at once without cutting each other off.

### Auto-advance AUTO

Not a line field: `AUTO` at the bottom-left of the dialogue box (native `main.psb.m` slice, `left:26 / top:1022`) is a global toggle. When lit, each line waits for the speaker's voice (plus that line's `wait`) before advancing; clicking the screen advances immediately. The state is kept in localStorage.

### Blinking blink

The rhythm follows the wasm's built-in auto-blink, driving `face_eye_open` up to `10` (closed) along a 10-frame curve and back every 1.3–3 s.

- Configured **per character**: `cast.json`'s `blink` (`on` defaults to `true`, `closeValue` to `10`; `vars` / `track` can rename variables).
- **Actions no longer override it** — all actions follow the character's single setting.
- Timers start for **all** characters once blocking settles; page turns / scene changes / endings / entering edit mode stop them and zero the diff.

<details>
<summary>🔍 Expand: how blinking works internally</summary>

**Per-model variables**: `face_eye_open_l` / `_r` are the actual eyelids (0 open / 5 half / 10 closed / 55 special), while the SDK only drives singular `face_eye_open`, so L/R must be filled in by us. Models without those two declarations are left alone to avoid double closure.

**Driving**: `setVariableDiff` (module `blink`), added on top of the base and written back to 0 when idle. Each frame does one linear follow:

```
k    = (track - trBase) / (10 - trBase)
diff = (closeValue - current lid value) * k
```

Two details matter:

1. **Relative baseline**: the resting value is raised by expressions (Suzuha angry = 2, Kurisu surprised = 8). The baseline is detected by rate of change: shifts slower than `0.015` units/ms count as expression fades and are followed directly; after a fast change (a blink is 0.02~0.12) drift is ignored for 250 ms so a pause at the peak is not mistaken for a new baseline.
2. **Close the gap, don't add a constant**: the lid base is not 0 (surprised -5, angry 4), so a plain `+closeValue` under- or over-closes.

**Fallback**: if `track` stays pinned at full closure for over 250 ms, it is an action holding the eyes shut (e.g. Suzuha's head shake), so the code treats it as the baseline and zeroes the diff. The diff has no remove API; stopping the timer, swapping the lid variable, disabling blink or switching actions must all explicitly write 0.

</details>

## 🎛️ Editor workbench

Entry: `steins_gate/edit/index.html` (from "Edit ↗" on the story page). A separate wasm instance keeps editing and playback independent in memory.

**Three top-bar views**

| View | Contents |
|---|---|
| Script | Line editing + multi-track timeline (lines / BGM / SFX / voice / background) |
| Timeline | All-track overview, drag segments, box-select and delete |
| Cast | Roles / action macros / properties in three columns; audit, rename, delete (`Esc` to return) |

**Layout**: left column has a "Project drawer" (script / title rows) plus a "Resources drawer" (background / BGM / SFX / history, drag-sortable with collapsed-state memory); right column has three cards — "Line / Voice library / Cast on stage". Drawer width and order are stored in localStorage.

**Key points**

- **Cast on stage**: each card has four rows — role dropdown + keep/enter/exit + remove; position and scale (line 1 writes `stage`, later lines write `move`; grey = inherited, orange = overridden); this line's action and voice (speaker writes line-level fields, others write `cues`); binding (model dropdown + voice directory).
- **Action macros**: pick "Custom…" to expand main timeline / diff slot 1 / diff slot 2, name it and click "Save macro" to write into `cast[role].actions`.
- **Display names everywhere**: the line list, speaker dropdown and role-card dropdown all show the `cast` display name (internal id appended when customized).
- **One "Save"**: scene and `cast.json` are written together; the cast tab has no separate save button.
- **Variable import**: in LAB "Variable tuning" → "Copy params", then in the cast tab select an action macro → "Paste import" to bulk-add variable rows. Names come from the current model's `variableList`, with "Custom…" for new ones; `Ctrl+Enter` imports quickly.
- **Theme switching**: the palette button in the top bar toggles two color schemes — teal and graphite orange — remembered in localStorage.

> 💡 Switching to a scene that needs new models reloads the page once; changing a model in a role card shows a "save and reload to take effect" hint.

## 🔧 Technical notes

**Why parse PSB ourselves**: the wasm exports 84 interfaces, but model metadata exposes only `charaProfile` / `charaBounds` — no atlas rectangles, `source` table, or `customSelectorList`. Exclusive arms cannot be enumerated at the SDK layer, so the bytes must be read directly — the sole reason `PsbReader` exists. It reads only the structure region (~1 MB) and skips ~200 MB of texture data, taking roughly 10 ms in-browser.

**Why patch at the texture layer**: the 3.9.8 runtime does not understand PSB 4.0 `insert` / `delete`, so it draws both arm sets. The unused arm rectangles are erased to transparent during `texImage2D` upload, leaving the SDK untouched.

## ⚠️ Known limitations

- Only unencrypted, uncompressed PSB v4 `pure.psb`; MDF / PSZ wrappers, PSB v3 or other platform exports need extra handling.
- Depends on the 3.9.8 runtime; future SDK changes may invalidate the texture-patch assumptions.
- Hit areas rely on the model's `charaProfile`; models without it degrade to no reactions.
- Thumbnails are keyed by source file name; replacing an image with a new file of the same name does not invalidate the old thumbnail — delete `.thumbs/<name>.jpg` to regenerate it.
